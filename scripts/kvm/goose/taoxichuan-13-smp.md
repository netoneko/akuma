## The gap
Taoxichuan runs on ONE core. The guests we boot are given 4 vCPUs (`vcpus=4`, cores 4-7 on the host) and only vCPU 0 is ever started: the whole kernel assumes a single core - `exec_twin::CURRENT` is a plain static ("the SMP slice puts `%gs` behind the body, never the callers"),
`TASK_SLOT` is one static, the `BorrowCell`s (`SLOTS`, `TASKS`, `SLOT_STATE`, `PIPES`, `OWNED_ROOT`, ...) PANIC on a second borrower - correct on one core, a crash the moment two cores meet -, `ring3`'s syscall stack top and user-rsp stash are single globals, the GDT/TSS/trap stack are single, and the
LAPIC timer is armed on the boot core only. `docs/gaps.md` lists it ("No scheduler beyond the slice-3 switch ... SMP slice 5", "No BKL"). The payoff: the in-guest `-j4` kernel build (5.5 min on one core... of four) and `goose` use the cores we already pay for.

## Design (decide, justify in the result file; simplest correct first)
**Big kernel lock, as `smp-shared` does:** ring 3 runs in parallel; every kernel entry (syscall, fault, tick IRQ) takes the BKL (`akuma_bkl`), so all the kernel statics stay single-writer and the `BorrowCell`s keep working unchanged - they become a *check* that the BKL is held, not a lock.
Per-CPU state goes behind `%gs` (the `current_slot` body), not new statics: current task/slot, syscall stack top and user-rsp stash (the `syscall` stub reads them per core), trap stack, TSS, GDT, LAPIC id, need_resched. APs: a real-mode trampoline page + INIT/SIPI from the BSP (`amd64/src/smp.rs` is the working reference - **extract the AP bring-up and the per-CPU block into a crate
(`akuma-smp-amd64`; `forbid(unsafe_code)` where possible, `unsafe` behind one stated contract) and make `amd64/` depend on it too**, then pull it from `taoxichuan/`: composition rule - pull, extract, write new only with a reason), per-core LAPIC timer + idle thread (`seed_idle` per core; the boot thread is adopted as slot 0 - re-read `SMP_ADOPTED_IDLE_SLOT_CLOBBER.md`),
the picker running on every core (`can_run`, cross-core wake IPI instead of `wake_remote_idle: || false`), TLB shootdown on `munmap`/`mprotect`/CoW (IPI to cores running the same CR3 - the box already hit "mmap_regions shootdown deadlock" once; `docs/archive/` has it), fxsave areas per core. Fine-grained locking is a later slice, only if the BKL is the measured bottleneck.
Staging: S-a `smp=1` unchanged-green with the new per-CPU plumbing (`%gs`, locks as no-ops); S-b APs online, idle, ticking, running only the idle thread (`[smp] cpu N online`); S-c the picker hands user tasks to APs under the BKL (`smp=2`, then 4); S-d shootdown + the stress. A `smp=N` kernel cmdline token (default 1 until S-d is green, then default = all CPUs the MADT lists), like amd64's `set_cpu_cap_from_cmdline`.

## Traps
A hang under SMP is usually a lost IPI, an AP stuck before its stack is valid, a `BorrowCell` panic (read the message: it names the nested borrow), or the BKL taken twice (re-entrancy: the dispatcher calls helpers that themselves enter - take it once at the outermost entry). Capture the console of each core (`[KVM] cpu:` lines show which vCPU burns). A hung guest on the box: kill its `vm-run` by pid (never `pkill -f`).
