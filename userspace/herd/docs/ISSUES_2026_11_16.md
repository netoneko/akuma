# herd issues (review, 2026-11-16)

A source read of `userspace/herd/src/main.rs` (the daemon, config parser, control socket and
CLI), followed by fixes on branch `userspace-review`.

| # | Severity | Issue | Status |
|---|---|---|---|
| H1 | Medium | Boolean keys disagreed on spelling: `oneshot = yes` read as false | fixed, verified live |
| H2 | Medium | ` # comment` after a value became part of it; numbers silently fell back to defaults | fixed, verified live |
| H3 | Low | Unknown keys (typos) were skipped without a word | fixed, verified live |
| H4 | Medium | A config file that could not be read stopped and removed its service | fixed |
| H5 | Low | "Reloading config..." every 20 s, and every config re-parsed each time | fixed, verified live |
| H6 | Medium | `workdir` ignored for boxed/`join_box` services, and a bundle's `process.cwd` ignored | fixed |
| H7 | Medium | The core_init fallback spawned a stripped-down copy of the service | fixed |
| H8 | Low | Log size started at 0 on every herd start; rotation read the whole log into memory | fixed |
| H9 | Low | File writes ignored short writes and reported success | fixed |
| H10 | Medium | CLI names were not validated (`herd add ../x`); every CLI command exited 0 | fixed, verified live |
| H11 | Medium | `start`/`stop` on the control socket needed no credential | fixed, verified live |
| H12 | Low | A silent control client could stall the supervisor for 1 s per connection | fixed |

## H1–H3. Config parsing

- **H1.** `backoff` and `console` accepted `yes`, `boxed` and `oneshot` did not, and `restart` was
  true for anything except `false`/`0`/`no`. So `oneshot = yes` made a service that restarts
  forever. `parse_bool` now gives every key the same set: `true/yes/on/1`, `false/no/off/0`.
  Anything else keeps the default and logs a warning.
- **H2.** The README's own example, `restart_delay = 1000 # ms`, did not parse as a number. It
  only worked because the fallback default is also 1000. `restart_delay = 5000  # five seconds`
  silently gave one second. `strip_inline_comment` drops a `#` that follows whitespace, on every
  key except `env`, whose value is taken whole. A number that does not parse keeps the default
  and says so.
- **H3.** Unknown keys are still skipped (a newer config must load on an older herd), but with a
  warning.

## H4–H5. Reload

- **H4.** A `.conf` listed in the enabled dir that could not be read this time was left out of the
  list. The removal pass then treated the service as disabled, and stopped and removed it. A
  transient read error took a running service down. Unreadable files are now kept in the list,
  and their services are left as they were. (A file that stops parsing already kept the service's
  previous config. Now the log says so, once per edit.)
- **H5.** Every 20 s herd printed `[herd] Reloading config...` to the console and re-parsed every
  file, so a bad line's warning would repeat forever. Each service keeps the text it was parsed
  from (`config_text`), and a reload re-parses only changed files, logging `Config changed: <svc>`
  once. Rejected texts are remembered the same way (`rejected_configs`).

## H6–H7. Spawning

- **H6.** `spawn_in_box` hard-coded `cwd = "/"`. `workdir` on a boxed or `join_box` service did
  nothing, and so did an OCI bundle's `process.cwd`, which `parse_oci_config` already parsed. It
  now takes a cwd (inside the box): `workdir` if set, otherwise the bundle's `process.cwd`,
  otherwise `/`.
- **H7.** When `core_init` was unavailable (every shared-kernel SMP boot), herd fell back to a
  bare `spawn(command, args)` for a service pinned with `core = N`. That spawn dropped `env`,
  `workdir`, `console` and `cpus`, and never set `started_at_ms`, so every exit counted as a quick
  failure for `backoff`.
  The fallback now calls `start_service` again with `core = 0`, which takes the normal path.

## H8–H9. Files

- **H8.** `log_size` started at 0 in `SupervisedProcess::new`, so after every herd restart a log
  could grow another `MAX_LOG_SIZE` past the limit. It now starts from the file's size
  (`existing_log_size`). Rotation read the whole log (up to the VM log limit) into memory and wrote
  it back as `.old`, on the supervisor's thread. It is now `rename`.
- **H9.** `write_file` issued one `write` and returned true whatever happened, and `append_file`
  returned nothing. Both now loop over short writes (`write_all_fd`) and report failure.
  `herd enable` removes a half-written copy.

## H10–H12. CLI and control socket

- **H10.** Service names went straight into paths: `herd add ../x` wrote outside
  `/etc/herd/available`. `valid_service_name` (one word, no `/`, no leading `.`, at most 64 bytes)
  now guards the CLI and the control socket. `add`, `config`, `enable`, `disable` and `log` exit 1
  when they fail; they all exited 0 before. Read-only commands no longer `mkdir` the directory
  tree as a side effect. Verified live: `herd add ../evil` and `herd stop .x` are refused with
  exit 1, and `herd log nosuch` exits 1.
- **H11.** The control socket is loopback TCP, so any process that can reach loopback could stop
  any service, including boxed services sharing the host's network stack. In September the
  kernel's any-address bind put it on the LAN
  (`docs/archive/AKUMA_NET_LOOPBACK_BIND_EXPOSED.md`). The daemon that owns the socket now writes a
  random 128-bit token to `/var/run/herd/control.token` (0600, temp file and rename), and
  `start`/`stop` must carry `token=<hex>`. `status` does not need it. Requests are no longer echoed
  into the log, since they carry the token. Compatibility: a daemon with no token accepts bare
  requests, and a CLI with no token file sends them, so old and new binaries mix during an upgrade.
  Verified live: requests without the token get `err not authorized`, and the CLI's `stop`/`start`
  succeed.
  **Limit:** the kernel does not yet enforce file modes (security audit H1, DAC). Until it does,
  the token keeps out what cannot see the host's `/var/run` (a box with its own root), not a host
  process.
- **H12.** `read_request_line` waited up to 1 s for each connection's request, during which nothing
  else was supervised, and up to 8 connections were served per tick. The timeout is now 250 ms,
  and `serve_control` stops taking new connections after 500 ms in one tick.

## Verification

- Host: `cargo test --bin herd --target <host>`, 22 passed, with new tests for `parse_bool`,
  inline comments, name validation, the token in `parse_request` and `authorized`.
  `cargo test -p herd --lib --no-default-features --target <host>`, 28 passed.
- Builds for `aarch64-unknown-none` and `x86_64-unknown-none`.
- Live, QEMU aarch64 guest: the guest's herd was replaced by the new one with a scratch
  `--enabled-dir`. Checked:
  - `oneshot = yes` completed;
  - `command = /bin/sh   # the shell` parsed;
  - `workdir = /tmp` gave `pwd` `/tmp` (an unboxed service; the boxed path, H6, was not run live);
  - the unknown-key and bad-boolean warnings printed once;
  - one `Config changed` line over two quiet reload cycles;
  - the token file was 0600, and the token was refused or accepted as described.
- Not run live: H4 (needs an unreadable file, and the guest runs as root), H7 (core_init) and
  rotation (H8).
