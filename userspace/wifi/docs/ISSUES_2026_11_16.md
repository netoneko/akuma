# wifi issues (review, 2026-11-16)

A source read of `userspace/wifi` (`src/{lib,main}.rs`), followed by fixes on branch
`userspace-review`. The tool manages `/etc/wifi/<network>` files and drives `/dev/wifi0`; the
kernel does the WPA2 handshake.

| # | Severity | Issue | Status |
|---|---|---|---|
| W1 | Medium | `save` truncated the file in place: a crash or full disk left a network file that would not parse | fixed |
| W2 | Medium | `wifi add` echoed the passphrase to the terminal | fixed |
| W3 | Medium | `wifi forget` could not remove a file that did not parse | fixed |
| W4 | Low | Re-adding a known network reset its priority, autoconnect and bssid | fixed |
| W5 | Low | `wifi scan` marked a network known by SSID alone, whatever its security | fixed |
| W6 | Info | A hand-written `passphrase =` value is trimmed | documented |

## W1. Non-atomic save

`save` opened `/etc/wifi/<name>` with `O_TRUNC` and wrote the new text into it. A crash or a full
disk after the truncate left an empty or short file in place of a working one. `wifi auto`
refuses to use a file that does not parse, so on a box reached over wifi that is the box gone.
`save` now writes `.<name>.tmp`, makes it 0600 before writing the key (as before), and renames it
over the real file, so the old file stays until the new one is complete. The `chmod 0700` of
`/etc/wifi` was unchecked; now a failure stops the save.

## W2. Passphrase echo

`wifi add` read the passphrase from stdin with echo on, so it landed on the screen and in any
terminal recording. It now clears `ECHO` (TCGETS/TCSETS on fd 0, `lflag` at offset 12) for the read
and restores it afterwards. When stdin is not a terminal, TCGETS fails and nothing changes, so
`wifi add x < file` still works.

## W3. A broken file could not be forgotten

`forget` loaded the file first and stopped at the parse error, so the one command meant to remove
a network could not remove a broken one, and `rm` was the only way. It now validates the name,
unlinks the file whatever its contents, and disconnects only when the file parses and names the
current link.

## W4. Re-add reset settings

`wifi add` for an existing name wrote a fresh `Network` with default priority and autoconnect and
no bssid. Changing a password therefore also silently changed which network `wifi auto` prefers.
`replacing(new, old)` keeps the old priority and autoconnect, and keeps the bssid only if the SSID
is the same. The tool now prints `updated` or `added`. Host-tested.

## W5. Scan marks

`wifi scan` put `*` beside any network whose SSID matched a saved one. A saved WPA2 network and an
open network with the same SSID (the usual evil-twin setup) looked the same. `scan_mark` now gives
`*` only when a saved network can join that BSS, and `!` when the SSID is known but the security
differs. Host-tested.

## W6. Documented, not changed

A hand-edited `passphrase = ...` line is trimmed like every other value, so a passphrase with
leading or trailing spaces cannot be written that way. `wifi add` always stores the derived
`psk = <hex>`, so this affects only hand-written files. The README's Limits section now says so.

Checked and not a problem: `wifi join` right after `add` does not race the kernel. The station
moves to `associating` synchronously inside the `connect` write, so the first status read already
sees it.

## Verification

- Host: `cargo test -p wifi --lib --no-default-features --target <host>`, 12 passed (two new:
  `replacing`, `scan_mark`).
- Builds for `aarch64-unknown-none` and `x86_64-unknown-none`.
- Not run live: no `wifisim` boot was done for this review. W2 depends on the kernel's TCGETS
  layout, which is the `akuma-tty` wire format (`Termios::to_wire`, 36 bytes, `c_lflag` at 12).
