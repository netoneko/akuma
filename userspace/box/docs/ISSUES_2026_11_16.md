# box (and tar) issues (review, 2026-11-16)

A source read of `userspace/box` and the tar crate it links (`userspace/tar`, `akuma_tar`),
followed by fixes on branch `userspace-review`. `box pull` runs as root and feeds registry bytes
straight into tar, so tar's findings belong here.

| # | Severity | Issue | Status |
|---|---|---|---|
| B1 | **Critical** | tar wrote through symlinks: an image layer could overwrite any host file | fixed, reproduced live |
| B2 | High | Manifest digests were used as paths unchecked: a registry could point a layer at a host directory | fixed |
| B3 | High | `box run --name ../.. --rm` removed a host directory tree | fixed |
| B4 | Medium | `box rmi ..` removed all of `/var/lib/box` | fixed |
| B5 | Medium | A failed write during extraction was ignored; the layer was cached half-written | fixed, verified live |
| B6 | Medium | After one failed write, tar lost its place and silently dropped the rest of the archive | fixed, verified live |
| B7 | Low | Stale staging dirs and fixed `/tmp` names between pulls | fixed |
| B8 | Low | An image config over 64 KiB was truncated | fixed |
| B9 | Low | `/proc/boxes` read with one 2 KiB `read` | fixed |
| B10 | Low | `box grab 12a3` grabbed pid 123; junk fell back to the box's main process | fixed |
| B11 | Low | `box cp` followed symlinks, lost modes, held whole files in memory, exited 0 on failure | fixed |

## B1. Extraction escaped its root through symlinks (critical)

tar created each entry at `<root>/<entry path>` with ordinary path resolution. An earlier entry
in the same archive could make a parent component a symlink. A layer holding `etc -> /etc` and
then `etc/passwd` replaced the **host's** `/etc/passwd`, as root, during `box pull`. Pulling an
image is enough; nothing has to run.

**Confirmed** on a QEMU guest with the `697f1ca2` tar. A crafted archive with
`link -> /tmp/outside` and then `link/escaped.txt` produced `/tmp/outside/escaped.txt`.

**Fix.** `format::resolve_in_root` resolves every parent component inside the root with chroot
semantics: `..` stops at the root, an absolute link target is re-rooted under it, and more than
40 hops (`MAX_SYMLINK_HOPS`) is refused. `extract::Root` drives it with `readlink`/`fstatat`, and
caches the directories it has already resolved. A symlink at the final component is unlinked and
replaced, never followed. A hardlink's target is resolved the same way and is never a symlink.
Re-run with the fixed tar, the same archive lands in `<root>/tmp/outside/escaped.txt`, and the
host's `/tmp/outside` stays empty. Host tests cover re-rooting, `..` clamping, loops and the
final-component rule.

## B2. Unvalidated digests became paths

Layer and config digests from the registry's manifest were joined into store paths
(`/var/lib/box/layers/<digest>`). A digest of `../../..` (or one naming an existing host
directory) made the "already present" check succeed, and that host directory was stacked under
the container root. `manifest::check_digests` now requires every digest to be canonical
`sha256:<64 lowercase hex>` before anything uses it. `pull_image` calls it straight after
`fetch_manifest`.

## B3–B4. Names that leave their directory

- **B3.** The container name is a directory under `/var/lib/box/containers`, and `--rm` runs
  `remove_tree` on it when the container ends. `--name ../../..` pointed that at `/`.
  `paths::valid_container_name` enforces Docker's rule (`[a-zA-Z0-9][a-zA-Z0-9_.-]*`, at most 128
  bytes) in `box run` and `box commit`. A generated name (`default_container_name`) always passes
  it.
- **B4.** `sanitize_name` kept `.` and `..`, so `box rmi ..` removed the image store's parent. A
  leading `.` now becomes `_`, and an empty name becomes `_`.

## B5–B6. Extraction failures were invisible

- **B5.** A failed `open` or `write` printed an error, and extraction carried on. `tar` exited 0,
  and `box pull` cached the incomplete layer as content-addressed and complete, so every later
  container got the hole. A full disk was enough to trigger it. Failures are now counted
  (`Stats::failed`): `tar` exits 1, and `box pull` fails the layer and clears its staging dir.
  Short writes are retried (`write_all_fd`).
- **B6.** In the streaming path, a failed write `break`s out of the copy loop before counting the
  bytes it had already read. The caller then skipped the wrong amount of padding, and the next
  header failed its checksum ("bad header checksum, stopping"), so the rest of the archive was
  dropped without another error.
  **Confirmed live:** an archive of `plain.txt`, `plain.txt/x` (cannot be created) and `good.txt`
  left only `plain.txt` with exit 0 under the old tar. The new tar extracts both files, reports
  `failed 1`, and exits 1.

## B7–B12. Smaller items

- **B7.** Layer downloads used `/tmp/oci-layer-<i>.tar.gz` and staging dirs were reused, so two
  pulls collided and a failed pull left debris for the next. Temp names now carry the pid and are
  unlinked on error. Staging is removed before extraction and after a failure.
- **B8.** `fetch_config` read at most 64 KiB, and a larger config failed to parse. It now reads to
  EOF (`fsx::read_file`).
- **B9.** `/proc/boxes` was read with a single 2 KiB `read`, so a long list was cut short. It is
  now read to EOF.
- **B10.** `box grab` built the pid from the digits only, so `12a3` meant pid 123 (another
  process), and a string with no digits fell back to the box's main process. Anything but a
  positive decimal number is now an error.
- **B11.** `box cp` is rewritten. It uses `lstat`, recreates symlinks instead of copying their
  targets, keeps modes, streams through `fsx::copy_file`, counts failures, and exits 1 if any.
- **B12.** The deprecated `waitpid` folded a signal death into status 0, so
  `box run img cmd && next` carried on after a crash. `box run`, `open`, `use` and `grab` now use
  `waitpid_status` with the shell convention (128 + signal).

## B13. Open

`read_in_container` follows symlinks when it reads the image's `/etc/passwd` for `--user`
lookup, so an image can make box read a host file. The read is harmless: it is parsed for one
uid/gid line and never written or shown. It should still resolve inside the root, the way tar now
does.

## A kernel divergence found on the way (not fixed here)

`open("file/x", O_CREAT|O_WRONLY)`, where `file` is a regular file, **succeeds** on the AArch64
kernel; the later `write` fails with ENOTDIR. `ls file/` also lists `file`. Linux fails the
`open` with ENOTDIR. This is what made B5 visible as a write error rather than a create error.
It belongs in the VFS path walk.
