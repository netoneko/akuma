06 / The reference run

First, prove the target is reachable.

Before any agent writes a line, the reference Rust and Scala services are built and run inside Akuma boxes, and one Python acceptance suite checks them over HTTP from the second guest.

Verified. Both reference services run and the reference acceptance suite passes (main amd64 kernel: 19 ok/info, 0 failed; Denver: 18–20 ok/info, 0 failed). The agents' own builds are not part of this result.

01 / Rust box

Git server, built here

cargo build --release --locked with a pinned toolchain, crates.io and a git dependency; about 305–365 s at two CPUs.

02 / Scala box

Task board, run here

scala-cli on the JVM resolves its dependencies from Maven Central, then starts the board.

03 / Guest 2

Python suite over HTTP

The acceptance suite calls both services across guests, including a push to the git server.

04 / The bar

What the swarm must match

The same suite later judges the agents' services, so a failure is an agent failure or an environment fix.

07 / The real run · November 22–23, 2026

Three agents, three rounds.

A trial on two guests led from independent builds and test feedback to two kernel fixes and a successful Denver rerun.

01 / Main kernel

Build and test

Rust and Scala agents build in parallel; a Python agent tests both over HTTP. Git passes; the board has seven failing cases. The Python agent’s 40 board tests pass against the reference implementation.

02 / Feedback

Fix the board

The Scala agent receives the failure list and repairs validation order in 224 s. All 40 board tests and the reference suite pass.

03 / Denver

A stall reveals bugs

Rust finishes in 327 s, but Scala stalls for 40 minutes. Investigation finds an exec leader-slot reuse bug and a separate PTY reference bug.

04 / Denver rerun

Scala passes

After both fixes, the Scala agent finishes in 1,178 s. Its board and the earlier Denver Git service pass the reference suite from guest 2. The full three-agent Denver rerun is still ahead.

09 / Rounds 2–3 · Denver

A stall becomes a kernel fix.

The same trial on Denver exposed two environment bugs. The fixed kernel went back into a Scala-agent rerun.

Round 2 · Rust BGit service works

The agent finishes in 327 s.

Round 2 · Scala Cscala-cli stalls

The agent waits for 40 minutes.

Round 2 · Python DBoard unavailable

The tester reports the deployment failure.

→
Investigation of C's stallReproduce and probe

Work can finish while the parent or output stream still waits.

↓
Two separate causesExec slot + PTY references

Leader-slot reuse loses exit status; missing PTY reference hooks can stop output draining.

→
InterventionFix both kernel bugs

Reserve the leader slot and track PTY references across dup and fork.
