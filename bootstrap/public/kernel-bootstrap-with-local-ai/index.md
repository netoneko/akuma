# Kernel bootstrap with a local AI

**You are an autonomous coding agent (Claude Code, goose, aider, ...) running
inside a checkout of this repository.** This page tells you, end to end, how to
**build a kernel from this checkout and boot it** on QEMU or Firecracker on
Linux or macOS, and land in a shell inside it over SSH.

The userspace half — the most minimal rootfs image worth booting (sshd, busybox,
nightly rust+cargo) — is built by
[`overlays/simple-kernel-devbox/bootstrap.sh`](../../../overlays/simple-kernel-devbox/README.md).
Build the kernel, build the image, boot, ssh in. Every step below prints
something checkable; do not proceed past a step that did not print it.

Work autonomously. Do not ask a human which command to run — everything you
need is on this page or one link away. At the end, verify yourself against
[Definition of done](#8-definition-of-done).

---

## 0. Rules

1. **Work in the checkout you are already running in.** Do not clone a fresh
   copy into a sibling directory unless step 1 proves the current directory is
   not an Akuma checkout.
2. **Check out the branch `post-release-improvements`** before building. It is
   the branch this guide and the toolchain pins live on (it is also the ref the
   repo's `install.sh` pins). Do not build from `main` or from a detached HEAD.
3. **Never edit generated artifacts.** `target/`, `*.img`, `bootstrap/bin/` are
   outputs, not sources.
4. **The kernel is the artifact.** If you change kernel sources, you must
   rebuild and reboot — there is no hot reload. Userspace inside the VM can be
   edited in-guest.

---

## 1. Orient: is this an Akuma checkout?

Run, from your current working directory:

```bash
test -f Cargo.toml && grep -q '^name = "akuma"' Cargo.toml && echo akuma-ok
test -d overlays/simple-kernel-devbox && echo overlay-ok
```

Both must print. If not, you are not in the repo — clone it and move there:

```bash
git clone https://github.com/netoneko/akuma && cd akuma
```

Then:

```bash
git status --porcelain        # ideally empty; if dirty, commit or stash your work — never discard it
git checkout post-release-improvements
git log --oneline -1          # note the commit you are building
```

> On Apple Silicon this repo builds natively. On an x86_64 Linux host it also
> builds natively — the default cargo target is the freestanding
> `aarch64-unknown-none` (see `.cargo/config.toml`), which cross-compiles fine
> from any host; only *running* the result differs (see step 4).

---

## 2. Host dependencies

Check each; install what is missing. Do all checks in one pass:

```bash
which cargo rustc docker qemu-system-aarch64 mkfs.ext2 ssh git
rustc --version       # must say nightly-2026-09-19 (pinned in rust-toolchain.toml)
docker info >/dev/null && echo docker-ok
```

| Missing | macOS (Homebrew) | Debian/Ubuntu |
|---|---|---|
| rustup/cargo | `curl -sSf https://sh.rustup.rs \| sh -s -- -y --default-toolchain nightly` | same |
| docker | start **Docker Desktop** (image build loop-mounts via an alpine container) | `sudo apt-get install docker.io && sudo usermod -aG docker $USER` (re-login) |
| qemu | `brew install qemu` | `sudo apt-get install qemu-system-aarch64` |
| mkfs.ext2 | `brew install e2fsprogs` | `sudo apt-get install e2fsprogs` |

- The pinned nightly (`rust-toolchain.toml`) is fetched automatically by rustup
  on the first `cargo` command — do not fight it, do not override the pin.
  If `rustc --version` disagrees after install, you have a different toolchain
  first on `PATH`; `rustup which rustc` tells you which one wins.
- On Linux without a running Docker daemon there is no supported workaround
  for the image build in this guide — start Docker first.
- Apple Silicon: QEMU runs under **HVF** (hardware virtualization) — fast.
  x86_64 host: QEMU **emulates** (TCG) — correct but slow; expect minutes per
  boot, not seconds.

## 3. Build the kernel

Build the devbox-shaped kernel: userspace sshd via herd, real shared-kernel
SMP, native smoltcp network stack (no rump), boot self-tests compiled out.

```bash
cargo build --release --features devbox-smoltcp,no-tests
```

Expected: a clean `Finished` line, and

```bash
ls -lh target/aarch64-unknown-none/release/akuma{,.bin}
```

- `akuma` — the ELF (~4 MB); `akuma.bin` — the flat binary QEMU's `-kernel`
  eats (regenerated by `scripts/link_kernel.sh` at link time and again by
  `scripts/cargo_runner.sh` at boot; **always** regenerated, never trust a
  stale one).
- First build takes several minutes on a laptop; the tree is large (~140
  crates, but you only compile the kernel path).
- If it fails, the error names the crate; fix the source (you are an agent —
  read the error, edit, retry), or `git stash` and rebuild clean to separate
  your change from a pre-existing breakage.

Build-only equivalent used elsewhere in the repo:
`scripts/build_devbox_smoltcp.sh` (same feature set — keep any customization
in sync with it, `overlays/simple-kernel-devbox/run.sh` rebuilds with the same
flags).

## 4. Build the rootfs image

```bash
overlays/simple-kernel-devbox/bootstrap.sh
```

What it does, in order: rebuilds `herd`+`sshd` from `userspace/`, creates
`simple-kernel-devbox.img` (2560 MB ext2, `DISK=... scripts/create_disk.sh`),
copies **only** `{herd, sshd, busybox, apk}` into `/bin`, lays the full busybox
applet symlink set, installs the CA bundle + C toolchain via apk into the
mounted image, installs nightly `rustc`+`cargo` (+ rust-std, rust-src) from
static.rust-lang.org into `/usr/local`, and stages your
`~/.ssh/id_ed25519.pub` into `/etc/sshd/authorized_keys`.

Expected tail:

```
=== Done: simple-kernel-devbox.img (2560 MB) ===
-rw-r--r-- ... simple-kernel-devbox.img
```

Knobs (env vars, all optional — see the overlay README): image path/size
(`SIMPLE_KERNEL_DISK`, `SIMPLE_KERNEL_DISK_MB`), pubkey source
(`SIMPLE_KERNEL_SSH_PUBKEY`), offline skips (`SIMPLE_KERNEL_CA_CERTS=false`),
Rust removal (`SIMPLE_KERNEL_NIGHTLY_RUST=false`).

If the final WARNING says no pubkey was staged, fix it now (the default sshd
build requires publickey auth; there is no password):

```bash
docker run --rm --privileged \
    -v "$(pwd)/simple-kernel-devbox.img:/disk.img" \
    -v "$HOME/.ssh/id_ed25519.pub:/pubkey.pub:ro" \
    alpine:latest sh -c 'mkdir -p /mnt/disk && mount -o loop /disk.img /mnt/disk \
      && cp /pubkey.pub /mnt/disk/etc/sshd/authorized_keys \
      && chmod 644 /mnt/disk/etc/sshd/authorized_keys && sync && umount /mnt/disk'
```

ed25519 only. No key at all? `ssh-keygen -t ed25519 -N "" -f ~/.ssh/id_ed25519`.

Takes ~5–15 min (toolchain downloads). Re-runnable: it recreates the image
from scratch each time — anything you did in-guest is lost on a rebuild.

## 5. Boot it (QEMU)

```bash
overlays/simple-kernel-devbox/run.sh > boot.log 2>&1 &
```

Then **poll the log — never wait on the QEMU process** (it runs until killed):

```bash
until grep -aqE "\[herd\] Started sshd|\[SSHD\] Listening" boot.log 2>/dev/null; do sleep 2; done
echo up
```

Use `grep -a` — QEMU/HVF emits a control byte that makes plain `grep` treat
the log as binary. The markers in order:

1. `[Main] ...` boot banner (your kernel's commit/feature line)
2. `[SmolNet] DHCP configured / IP: 10.0.2.15/24` — smoltcp stack is up
3. `[herd] Started sshd` then `[SSHD] Listening on ...` — **ready**

`run.sh` sets `DISK=simple-kernel-devbox.img`, `MEMORY=4096`, `SMP=2` and goes
through `cargo run` → `scripts/cargo_runner.sh`, which forwards host
`2222 → guest 22`. Ports shift by `+100·INSTANCE` for parallel boots:

```bash
INSTANCE=1 overlays/simple-kernel-devbox/run.sh > boot2.log 2>&1 &
# ssh port becomes 2322; INSTANCE>0 also snapshots the disk (writes discarded)
```

Boot takes ~10 s on Apple Silicon (HVF), minutes under TCG. No output at all?
Raise `MEMORY` (there is a known sub-4 MB DTB limit) and see
[`docs/runbooks/debug-boot-hang.md`](../../../docs/runbooks/debug-boot-hang.md).

## 6. Connect and verify

```bash
ssh-keygen -R "[localhost]:2222" 2>/dev/null || true   # host key regenerates per image rebuild
ssh -o StrictHostKeyChecking=no -p 2222 root@localhost 'uname -a && rustc --version && cat /root/WELCOME.txt'
```

Expected: `Akuma akuma 0.0.7 <your-commit>-release-smp-shared aarch64 Linux`,
then the nightly rustc banner. Interactive shell:

```bash
ssh -o StrictHostKeyChecking=no -p 2222 root@localhost
```

In-guest checks (run over ssh, one command per line):

| Check | Command | Pass when |
|---|---|---|
| kernel is yours | `uname -a` | commit id matches `git log --oneline -1` from step 1 |
| shell + coreutils | `ls /bin \| head` | busybox applet symlinks |
| nightly toolchain | `rustc --version` | `rustc 1.1xx.x-nightly` from `/usr/local/bin` |
| **real build** | `cargo new /tmp/h && cd /tmp/h && cargo run --release` | `Hello, world!` |
| in-guest apk | `apk add -s git` | simulates fine (keys in `/etc/apk`) |
| filesystem writes | `echo hi > /root/x && cat /root/x` | `hi` (INSTANCE=0 keeps writes) |

`Permission denied (publickey)` means step 4's pubkey staging was skipped —
fix with the docker one-liner in step 4 and reconnect (no reboot needed).

## 7. Firecracker (optional second target)

Firecracker boots the **same** ext2 image; only the kernel binary format and
the host differ. Firecracker needs a **KVM host matching the kernel ISA**
(AArch64 here): an AWS `m6g.metal`, an ARM Linux box with `/dev/kvm`, or a
Lima VM on Apple Silicon (nested virt — `overlays/devbox-firecracker/host-setup.sh`
sets it up; `--local` flags target KVM metal directly).

```bash
# 1. FC-shaped kernel: raw Image with the ARM64 header, load-linked at 0x80300000
FC_FEATURES=devbox-smoltcp,no-tests overlays/devbox-firecracker/build.sh
#   -> akuma-fc.bin; the script asserts _boot's address and the Image magic,
#      because a wrong load address is a silent hang, not an error

# 2. Boot (mac default = via Lima; add --local on KVM metal)
FC_DISK=$PWD/simple-kernel-devbox.img overlays/devbox-firecracker/run.sh
```

SSH lands on host port **4444** (not 2222):

```bash
ssh -o StrictHostKeyChecking=no -p 4444 root@localhost 'uname -a'
```

Procedure + known-instability notes (one timing-sensitive boot-suite test is
expected to fail under nested virt — judge by `FAILED` > 1, not `FAILED=0`):
[`docs/runbooks/run-on-firecracker.md`](../../../docs/runbooks/run-on-firecracker.md).

> The **amd64** kernel is a separate target (`sh amd64/run.sh`, QEMU microvm;
> `amd64/run-firecracker.sh` for a remote x86 KVM host) with its own x86_64
> rootfs (`amd64/mkdisk.sh`). The image from step 4 is aarch64 userspace and
> will not boot there. Follow this guide's aarch64 path first.

## 8. Definition of done

You are done when ALL of these hold — verify each, in order:

- [ ] `git branch --show-current` → `post-release-improvements`
- [ ] `cargo build --release --features devbox-smoltcp,no-tests` → `Finished`
- [ ] `simple-kernel-devbox.img` exists and `bootstrap.sh` printed its `Done:` banner
- [ ] `grep -a "SSHD. Listening" boot.log` matches
- [ ] `ssh -p 2222 root@localhost 'uname -a'` prints your commit id
- [ ] `ssh -p 2222 root@localhost 'cd /tmp && cargo new h && cd h && cargo run -q'`
      prints `Hello, world!` — a real toolchain build inside the VM
- [ ] (if Firecracker was attempted) `ssh -p 4444 root@localhost 'uname -a'` works too

## 9. Iterate

The whole point of the devbox: change things and re-verify.

- **Kernel change** → `cargo build --release --features devbox-smoltcp,no-tests`,
  kill the VM (`pkill -f qemu-system-aarch64`), re-run step 5, re-verify step 6.
  Reboot takes ~10 s; `ssh-keygen -R "[localhost]:2222"` only after *image*
  rebuilds, not kernel rebuilds (the host key lives in the image).
- **Userspace change** → `userspace/build.sh --sshd-only`, then re-run
  `overlays/simple-kernel-devbox/bootstrap.sh` (rebuilds the image) or stage
  the binary into a running image with the docker one-liner from step 4.
- **In-guest experiments** (cargo/apk/vi) live in the VM; they die with it.
  Snapshot-worthy results go through the ssh session back to the host.

## 10. Troubleshooting

| Symptom | Fix |
|---|---|
| `bootstrap.sh`: `bootstrap/bin/<b> missing` | `SIMPLE_KERNEL_BUILD_USERSPACE=true` (default) rebuilds it; or run `userspace/build.sh --herd-only --sshd-only` |
| `bootstrap.sh`: docker errors | Docker daemon not running/not accessible (`docker info`) |
| `run.sh`: `$DISK not found` | build the image first (step 4) |
| Boot hangs before `[SSHD] Listening` | `MEMORY` too low, or see `docs/runbooks/debug-boot-hang.md` |
| `Permission denied (publickey)` | stage the key (step 4 one-liner); ed25519 only |
| `REMOTE HOST IDENTIFICATION HAS CHANGED` | image was rebuilt: `ssh-keygen -R "[localhost]:2222"` |
| Port 2222 busy | `pkill -9 qemu-system-aarch64`, or `INSTANCE=1` (port 2322) |
| `grep: boot.log: binary file matches` | use `grep -a` |
| First in-guest `cargo build` OOMs | `MEMORY=8192 overlays/simple-kernel-devbox/run.sh` |
