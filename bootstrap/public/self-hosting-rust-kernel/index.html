02

Capability test

Can a weak open model write a kernel that runs real workloads?

  • Why open models? Dario won’t let you write a Wi-Fi driver.
  • Akuma was mostly written by commercial models. GLM was the sidekick, and GLM 5.3 Flash built KVM from AMD’s spec PDFs.
  • Setup: about 10 days, a new kernel built from the code, docs and tests I already had.

05

Handoff and metal

Handed off to Sonnet, verified by GLM on bare metal

  • I handed off because I got tired of the resets and the quota grind.
  • Sonnet is the closest equivalent to GLM Flash, and big GLM is more capable than Sonnet, so open models can plausibly write acceptable kernel code. (My assessment, not a measurement: GLM was never tried on rustc and cargo.)
  • GLM ran the final self-hosting verification loop on bare metal.

K1 == K2, byte for byte.

06

Why Rust

Expressive, flexible, and it enforces discipline

  • Easy to measure the audit surface.
  • Composition: crates that arrived already debugged.
  • Host tests in leaf crates.
  • Inversion of control, forced by the pre-port refactor.
  • unsafe is countable and contained.
  • Drivers and KVM built from specs.

10

What’s next

Hardening, then verification

Hardening

  1. Read-only disk image, no ext2 write paths.
  2. Syscall table as a compile-time allow-list built from the census.
  3. No dynamic library loading.
  4. Execution locked to signed binaries under a signed kernel.
  5. Egress allow-list in the socket table.
  6. Kernel code locked by the hypervisor through nested page tables.
  7. Layered walls: box, ring 3 process, KVM guest.

Verification

  1. Fuzzing and static analysis on the pure crates.
  2. Kani and Miri on the invariants.
  3. LLM-drafted Verus proofs for small pure crates.
  4. Linux differential tests.
