02

Capability test

Can a weak open model write a kernel that runs real workloads?

  • Why open models? Dario won’t let you write a Wi-Fi driver.
  • My custom rust kernel Akuma was mostly written by commercial models and it was already self-hosting for a few months.
  • To speed up kernel development I used GLM 5.3 Flash to build KVM from AMD’s spec PDFs.
  • I had a talk in 10 days, a hypothesis, and a lot of free time.
03

The experiment

Speedrunning cargo build

  • Development runs on Akuma (GLM-5.3-Flash + Goose)
  • Sloppy methodology leads to questionalbe results
  • Every step ends in a gate a machine can check.
  • 390 interventions including real bangers like this one is a classic, read the docs with about 70% accuracy in guessing where the bugs are
  • GLM reached the equivalent of a self-hosting C kernel: HTTPS curl, apk, fork, pipes, all running on Akuma’s KVM.

AI is good at what you can verify.

  • Composition: 93% of Taoxichuan’s live lines were already live in Akuma, and a second kernel, Osaka, is 10 lines.
  • Host tests in leaf crates: the first test of the extracted madvise found that madvise(addr, -1, DONTNEED) looped over ~4.5e15 pages, reachable from unprivileged userspace.

07

Kernel that only runs tokio

Install a kernel from crates.io, and have your whole supply chain hijacked

  • Shanghai, new kernel built by GLM from a crate README.
  • This kernel runs tokio.
  • As a regrettable side effect, Python runs too.
//! Shanghai: a kernel built from the `akuma-tokio-kernel` README. The whole
//! kernel is this file plus a skyline.

#![no_std]
#![no_main]

akuma_tokio_kernel::entry!(main);

fn main(kernel: akuma_tokio_kernel::Kernel) -> ! {
    kernel
        .name("Shanghai")
        .banner(include_str!("banner.txt"))
        .console()
        .disk()
        .net()
        .smp()
        .run_init()
}

Real workload

GLM strips AWS out of an agent runtime, builds it, and runs it on the new kernel

664 → 399crates in Cargo.lock
21 → 11workspace members
−32,623lines (+2,453), 156 files
~18 minof build, six attempts
  • Unattended: goose with GLM, inside a Taoxichuan guest, under Akuma’s hypervisor on bare metal.
  • The job: clone infinity, cut every AWS dependency, build what is left (cut first, then build).
  • It swapped OpenSSL for rustls, since the guest has no OpenSSL headers, cmake or clang.
  • Proof: the agent answered PONG through api.z.ai, then ran uname -a through its own tool path.
  • Three of the six builds failed on kernel bugs, which were fixed along the way.
11

What’s next

Hardening, then verification

Hardening

  1. Read-only disk image, no ext2 write paths.
  2. Syscall table as a compile-time allow-list built from the census.
  3. No dynamic library loading.
  4. Execution locked to signed binaries under a signed kernel.
  5. Egress allow-list in the socket table.
  6. Kernel code locked by the hypervisor through nested page tables.
  7. Layered walls: box, ring 3 process, KVM guest.

Verification

  1. Fuzzing and static analysis on the pure crates.
  2. Kani and Miri on the invariants.
  3. LLM-drafted Verus proofs for small pure crates.
  4. Linux differential tests.
