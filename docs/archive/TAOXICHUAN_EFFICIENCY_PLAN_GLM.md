## 2. Top five by win-per-effort, each a ~100-call glm slice with a gate

**1. Demand-paged mmap past an eager threshold** (table #1) — biggest structural win; crates exist; attack surface well-bounded.
- Calls ~1-15: read `taoxichuan/src/main.rs` mmap arm + `fault_trap` + `docs/reference/memory.md`; read `crates/akuma-mmap` public API; decide: borrow `akuma-mmap` region table vs grow `Task.regions`.
- ~16-35: add `MMAP_LAZY` records (va, len, prot, fd/inode/off or anon) to Task; mmap only *records* past `MMAP_EAGER_MAX_PAGES` (port the akuma_config knob); keep the 64 MiB slab for eager small maps.
- ~36-60: fault arm in `fault_trap`: not-present+user+recorded → anon: `alloc_page_zeroed` (already zero-on-alloc in `akuma-pmm`), file: fill from `read_at_by_inode`. Must route through the same single break path as CoW (`cow_resolve` discipline: present+write goes there first).
- ~61-80: `munmap`/`mprotect` clip records; MAP_FIXED replaces; `copy_to_user` path unchanged (it can fault-fill too — note: kernel physmap writes don't fault, so fill explicitly like `cow_prepare_write` does).
- ~81-100: gates + battery.
- **Gate (console line/number):** `cargo build -j1` in a 3 GB guest completes; after exit, free pages return to ±1000 of baseline (`cow_leak_gate.py` reuse) and a new `[lazy] faults=N filled=M` line prints; `sh -c` quick-exec battery unchanged.

**2. File-page cache for RO file pages** (table #3) — cheap *after* #1; removes the documented -j4 thrash.
- ~1-20: read `crates/akuma-fpcache` (it is host-testable: `cargo test -p akuma-fpcache`), the eligibility list, and how amd64 wires it in `amd64/src/mm.rs`/`fs.rs`.
- ~21-55: wire insert/lookup into slice 1's file-fill arm (RO+file-backed only); map shared frame RO + COW-bit semantics; teardown = plain `free_page`.
- ~56-80: eviction: port `reclaim_clean_file_pages`-shaped pressure hook (only after 3 GB runs show pressure).
- ~81-100: gates.
- **Gate:** run the same toolchain page from two processes → `shared≥1 copied=0` in the `[reap]`-style counters; ext2 bytes-read per second `cargo build -j4` ≤ `-j1`'s; on KVM, `-j4` wall within 10 % of `-j1`.

**3. Syscall-floor audit + targeted dispatch fixes** (table #4) — cheapest, unblocks all other numbers.
- ~1-20: read `AKUMA_SYSCALL_PERFORMANCE_AUDIT.md`, `IDENTITY_CACHE_SMP_REVIEW.md` (the two jobs: lookup *and* liveness — Finding A/B), `IDENTITY_CACHE_LAZY_RESTAMP.md`.
- ~21-40: guest probe: N× getpid + futex wake loop, print ns/op from `exec_twin::uptime_us` (10 ms LAPIC ticks) or TSC (calibrated in `lapic_init`, per scheduling.md).
- ~41-70: audit `dispatch_inner` arms that call into `akuma-syscalls-linux`/`akuma-slot-table`: count resolutions per call; add the epilogue re-validation (Finding A) that the shared layer already learned the hard way.
- ~71-100: fix the worst arm (likely futex slot scan), re-measure.
- **Gate:** `getpid floor = X ns` line with X ≤ 200 on KVM; `futex_ab_run.sh`/`selfhost_probe_ab.sh` jobserver_stress green and not slower.

**4. Per-stage read(2) profiler + read A/B** (table #5) — the measurement slice that decides readahead.
- ~1-25: read `src/syscall/utils/read_profile.rs` (AArch64) + `read_stage_profile.py`; note its "within-one-boot" discipline (read_path_ab.py header: wall clock swings ~10 %/minute — host doc `EXT2_WRITEBACK_FOLLOWUP_FIXES.md` §8).
- ~26-60: port stage counters into taoxichuan's read arm (lookup / ext2 block loop / copy-out) behind a `read-profile` feature.
- ~61-85: run `apk add git`, `cargo build`, `git clone` windows; summarize with the py script.
- ~86-100: write one paragraph verdict: is block-read dominant? If yes, spawn slice "ext2 readahead" (table #6); if not, kill it.
- **Gate:** `[READPROF]` summary line per workload naming the dominant stage with µs and bytes.

**5. Wake budget + parked netpoll with IRQ doorbell** (table #7) — real but hardware-gated.
- ~1-20: read `crates/akuma-kacho` (all of it; it is small and policy-only), `amd64/src/sched.rs` WakeBudget use, `amd64/src/net.rs` daemon/doorbell.

## 3. Measurements the repo already has (predictors)

- **getpid 410 → 150 ns** (syscall audit `c2a0e630`) — docs/archive/`AKUMA_SYSCALL_PERFORMANCE_AUDIT.md`, `IDENTITY_CACHE_SMP_REVIEW.md`:28. Predicts slice 3's ceiling: ~260 ns of headroom *if* taoxichuan arms repeat slot lookups like the old path did.
- **Identity-cache hit rate 0.11 % → 99.999 %** under thread churn (556 M misses) after lazy re-stamp — `IDENTITY_CACHE_LAZY_RESTAMP.md` (before/after table, `identity_lazy_restamp` boot test). The lesson: *measure hit rate, don't assume*; one-shot stamps fail under churn.
- **fpcache problem statement numbers** — `crates/akuma-fpcache/src/lib.rs` header: `librustc_driver.so` 295 MB, `rust-lld` 154 MB; same text pages replicated per rustc + re-read from ext2; reclaim-evict-re-read thrash loop that `-j1` avoids. Predicts slices 1+2.
- **CoW gate methodology** — `scripts/kvm/goose/cow_leak_gate.py --cycles 20`: 60 fork/exec/exit rounds, `base=654000 end=654000 delta=0 PASS`, `cowrefs=0`, shared/copied/taken counters. Directly reusable as slice 1/2's memory gate; COW doc also reports `223948 frames shared instead of copied by the third build`.
- **A/B script family** — `scripts/benchmarks/`: `read_path_ab.py` (path-resolution cost, per-fd inode lever — the win taoxichuan already has), `read_stage_profile.py` (+ `read-profile` feature), `amd64_fault_cost.py` (price of one demand fault — run it on TCG before betting on laziness), `selfhost_probe_ab.sh` (jobserver_stress: futex/sched/mmap A/B, aarch64 vs amd64), `futex_ab_run.sh`, `mem_ab_run.sh`, `epoll_ab_run.sh`, `locks_rw_ab.sh`, `pin_reclaim_ab.sh`, `redis_matrix.sh`/`redis_bulk_ab.py` (netpoll/net win), `sqlite_wal_stress.py`.
- **Self-host timing anchors** — agent log: vendored `cargo build -j1` 2 m 45 s; `-j4` 2 m 46 s on one vCPU (concurrency, not speed); crates.io `-j4` build 2 m 46 s under KVM 8 GiB. These are the baseline wall-clock numbers slices 1+2 must beat in a 3 GB guest.
- **Known wall-clock caveat** — `read_path_ab.py` header + `crates/akuma-ext2/README.md` §Performance: host wall clock swings several-fold between sessions, ~10 %/minute ⇒ **A/B within one boot**, never across boots.

## 4. NOT worth copying on a single-core TCG/KVM guest

- **PCID/INVPCID or ASID-tagged TLB on amd64** — the amd64 kernel itself doesn't use PCID (grep: no hits in paging/mm); AArch64's ASID allocator (`crates/akuma-mmu/src/asid.rs`, 256 ASIDs + TTBR free gate) is AArch64 machinery. One vCPU switches address spaces rarely (and fork now shares instead of rebuilds); a full CR3 load is already in the noise. Also amd64's SMP **TLB shootdown** (`amd64/src/shootdown.rs`) has no target on one core.
- **SMP wake placement / scheduler calibration sweeps** — `akuma-scheduler`'s `WakePlacement`/`sweep(sched, netpoll, wake)` and `akuma-bkl` per-core hold tags optimize multi-core runs the agent log already dismissed: "`-j4` buys nothing on one core, it proves the concurrency". taoxichuan's tick is 10 ms with a single slot table; only the netpoll policy knob matters (slice 5).
- **smoltcp/rump dual network stacks, wifi (rtw89/ieee80211), USB/xHCI, HDA, NVMe/DMA-async paths, Firecracker/kvm-abi paravirt** — different hardware ambition; taoxichuan's rig is virtio/rtl8169-class over TCG/KVM. Copying any of these is weeks of work for zero measurable win on the self-host gate.
- **Full eviction/reclaim machinery before laziness exists** — `reclaim_clean_file_pages`/`try_evict_ro_page` fight pressure that post-CoW taoxichuan barely has (654000 free pages stable; 223 k frames shared). Adopt only after slices 1-2 create real reclaimable clean pages (and only if the 3 GB run shows pressure).
- **ext2 readahead *now*** — nothing to copy (no kernel in the repo has it), single vCPU can't overlap it well, and TCG disk is already fast; let slice 4's numbers decide, don't pre-build.
- **Wholesale identity-cache port** — taoxichuan's `task()` (one volatile read + array index) is *cheaper* than the shared layer's cache hit. Only the audit + arm-level fixes (slice 3) transfer.
- **Pipe/socket zero-copy machinery** — taoxichuan's pipes are counted kernel buffers (`akuma-pipes` table, `OpenFile::Pipe/Pair`, `ChildOut` drain buffers, taoxichuan/src/main.rs ~884-920), same shape as the amd64 kernel's; data is copied once per side, which is inherent at these sizes. A splice/vmsplice layer is self-host-irrelevant (cargo/cgit don't use it).
